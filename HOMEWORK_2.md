# Домашнее задание 2 — ошибки

## Что делаем

В шаблоне `main.go` лежит маленький диспетчер: он получает запрос, находит провайдера и задаёт ему вопрос. Сейчас в нём нет ни одной ошибки — все функции всегда возвращают `nil`. Твоя задача — добавить ошибки и решить две вещи:

1. **Какого вида** должна быть каждая ошибка.
2. **Где** каждую ошибку обработать, а где вернуть выше.

## Как начать

1. Создай ветку `lesson_2`.
2. Замени свой `main.go` шаблоном. Он сделан из твоего кода: типы те же, у `Provider` добавились поля `Enabled` и `Status`.
3. Запусти `go run .`. Программа упадёт с паникой на запросе 3 — так и должно быть, с этого и начнёшь.

## Что есть в шаблоне

Все нужные функции в шаблоне уже есть, но пока они «пустые»: ошибок не возвращают и не различают. Новые функции писать не нужно — нужно дописать эти. Они вызывают друг друга по цепочке:

```
main  →  dispatch  →  findProvider
                   →  Ask  →  check
      →  react
```

| Функция | Что делает |
| --- | --- |
| `check` | Проверяет, может ли провайдер ответить на вопрос |
| `Ask` | Провайдер отвечает на вопрос. Уже вызывает `check`, менять не нужно |
| `findProvider` | Ищет провайдера по имени |
| `dispatch` | Находит провайдера и задаёт ему вопрос |
| `react` | Получает ошибку и возвращает строку-реакцию для `main` |

Места, где от тебя требуется действие, отмечены в коде комментариями `TODO` с номером шага. Функцию `main` менять не нужно: провайдеры и восемь запросов уже подобраны так, чтобы сработала каждая ситуация.

## Шаг 1. Добавь ошибки

Ниже семь ситуаций. В какой функции возникает каждая — подсказывают комментарии `TODO` в коде. А вид ошибки выбери сам:

- **простая** — `errors.New("...")` или `fmt.Errorf("...")` прямо в месте возврата;
- **именованная** — `var ErrSomething = errors.New("...")`;
- **кастомная** — свой тип с полями.

| № | Ситуация | Что в итоге должно произойти |
| --- | --- | --- |
| 1 | Провайдера с таким именем нет | `main` печатает: «запрос отброшен: неизвестный провайдер» |
| 2 | Вопрос пустой | `main` печатает: «запрос отброшен: пустой вопрос, повторять бессмысленно» |
| 3 | Провайдер выключен (`Enabled == false`) | `dispatch` сам задаёт тот же вопрос провайдеру `anthropic` и возвращает его ответ. До `main` ошибка не доходит: он печатает ответ, как при обычном успешном запросе |
| 4 | API ответил кодом 429 (`Status`) | `main` печатает: «<провайдер>: слишком много запросов, повторим позже» |
| 5 | API ответил кодом 401 | `main` печатает: «<провайдер>: проверь ключ доступа» |
| 6 | API ответил любым другим кодом, кроме 200 | `main` печатает: «<провайдер>: неизвестная ошибка API, код <код>» |
| 7 | Провайдер выключен, и `anthropic` тоже не смог ответить | `main` печатает: «не удалось обработать запрос: » и текст ошибки. Особой реакции на эту ситуацию нет |

Пример для ситуации 3: запрос 4 адресован провайдеру `deepseek`, а он выключен. Тогда на вопрос отвечает `anthropic`, и в выводе появляется строка `4: [anthropic/ai-1] ...`. Имя запасного провайдера лежит в константе `fallbackProvider`.
**Подсказка, как выбрать вид.** Задай себе два вопроса:

1. Будет ли код выше проверять именно эту ошибку, чтобы решить, что делать?
2. Если будет — ему достаточно узнать, *что* случилось, или нужны ещё и данные?

## Шаг 2. Реши, где обрабатывать

Для каждой ошибки в каждой функции у тебя есть ровно два варианта:

- **вернуть выше** — если эта функция не знает, что с ошибкой делать;
- **обработать здесь** — если знает. Тогда выше ошибка уже не идёт.

**Главное правило: ошибку обрабатывает тот, кто знает, что с ней делать. И только один раз.** Либо ты на ошибку реагируешь, либо возвращаешь её — но не то и другое сразу.

Посмотри на таблицу из шага 1 и на колонку «что в итоге должно произойти». По ней видно, кто реагирует на каждую ситуацию. Одна из них обрабатывается не в `main`.

Когда возвращаешь ошибку выше, добавляй к ней контекст — что ты пытался сделать.

## Шаг 3. Реакция в main

Допиши функцию `react`: она получает ошибку от `dispatch` и возвращает строку-реакцию из таблицы. `main` её уже вызывает.

## Что должно получиться

```
1: [openai/gpt-4o] hello from api: what is a goroutine?
2: запрос отброшен: пустой вопрос, повторять бессмысленно
3: запрос отброшен: неизвестный провайдер
4: [anthropic/ai-1] hello from api: v1.01 what is a channel?
5: grok: слишком много запросов, повторим позже
6: gemini: проверь ключ доступа
7: mistral: неизвестная ошибка API, код 503
8: не удалось обработать запрос: ...
```

Текст после «не удалось обработать запрос:» будет твой.
